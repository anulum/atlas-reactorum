# Changelog

All notable changes to this project are documented here. The format follows
Keep a Changelog, and the project adheres to Semantic Versioning.

## [Unreleased]

  fields across the 172 research-reactor identities. Add 275 source-backed

## [0.1.0] — 2026-10-03

First public release of the source-linked atlas, static presentation and offline research library.

- Open directly on the interactive world map, with locations, source-linked
  details, search, filters and zoom visible before the supporting library.
  Keep desktop/mobile navigation and existing shared section links intact.
  Keep the complete map visible on initial mobile entry across system fonts.

- Accept an explicitly verified public historical input bundle for offline
  presentation builds, recording all nine source hashes. Preserve distinct
  original-input requirements for complete historical reconstruction.
- Verify separate historical report destinations and specific integrity
  refusals through the original command-line tools in both Python modes.
  Keep unexpected interpreter and filesystem exception details out of refusals.

- Reproduce the existing round-4 and round-5 research reports with their
  original provenance headers, retaining all report values and source inputs.

- Retain strict source-specific terms checking while accepting the reviewed
  Swiss portal page whose sole byte change is its global dataset counter.
  The original usage terms and dataset attribution requirements are unchanged.

- Add a source-linked research notebook and bounded CLI/API restoration of
  original comparison downloads with explicit whole-profile and file hashes.
  Preserve original statements, locators, rights and missing numeric values;
  refuse changed or unavailable source snapshots.
- Retain complete original evidence-profile snapshots with explicit Atlas
  observation dates, claim/source revisions and dated removal/return identities.
  Add exact historical links, source-preserving downloads and locally prepared
  pending corrections with separate curator decisions and reviewed source edits.
  The native offline build validates the retained journal and reproduces 22
  products without inventing source dates or automatically promoting proposals.

- Propagate the selected development Python into taxonomy validation from both
  `make build` and reproducibility preflight. Preserve explicit `ATLAS_PYTHON`
  selection and refusal instead of depending on an ambient Python's packages.

- Add six source-linked learning paths spanning water loops, magnetic
  confinement, chemical flow, wastewater treatment, electrochemical processes
  and neutron-source evidence. Overview/research depths retain identical
  evidence downloads; answer feedback cites the original statement and scope.
  Share links bind data and learning-content hashes and refuse stale versions.

- Add ordered stable-ID comparisons, complete-profile snapshot share links
  and source-preserving JSON downloads, with explicit missing-value/context
  limits and refusal of unavailable linked data versions.

- Add source-bound evidence profiles for all 135 entries, retaining all 599
  citations, 148 sources and original taxonomy/audit values.
- Add explicit snapshot validation and migration APIs, two versioned exports,
  keyboard-accessible questions and single-profile JSON downloads.
- Preserve original export formats and unknown dates; keep provisional entity
  mapping separate from source support and independent whole-entry review.
- Correct the dated validation history of the repaired shared JSON and
  publisher copyright compatibility findings.

The FFDB input is now an explicit data-only selection with separate artifact
and original-response hashes. All visible raw/display source cells remain
unchanged; the full renderer and permission-page HTML are retained privately.
The registered producer refuses mismatched source kind, origin or acquisition
date. Publisher data uses its source-specific permission reference.

### Catalogue, data and repository changes

### Repository hygiene

- Reconciled validation commands, architecture and trust boundaries with the
  pinned FFDB default, complete Python source enumeration and explicit local
  browser mode. Current focused evidence is separated from historical
  whole-suite measurements and unresolved security or source-rights decisions.
- Added exact JSON ownership sidecars for authored FFDB acquisition manifests,
  keeping publisher payloads and their redistribution review separate.

- Standardised hidden provenance comments throughout the documentation,
  including the generated field-completeness report.
- Added explicit version-one to version-two migration for generated industrial
  source provenance, with exact ordinary frozen reproduction retained.

### Fixed

- The original Swiss industrial test corpus is now included by the repository
  file rules, retaining its exact bytes, source-specific terms and attribution.
- Subcritical-assembly taxonomy now distinguishes the operating condition from
  a particular assembly's ability to reach criticality. The exact IAEA section
  replaces the blanket claim that design excludes all reactivity excursions.
- Dataset inventory counts the ten supplemental records rather than the
  three keys in their document wrapper.
- Corrected the Gauss GIGA citation to *World Fusion Outlook 2024*, printed
  page 21, after checking the original IAEA document.
- Company depth overlays now update current fields and presentation aliases
  together, including source dates and evidence links. Regenerated company
  JSON and JavaScript agree across all 39 enriched profiles. Current reference
  lists use the latest reviewed links without retaining superseded citations.

### Added

- Pinned IAEA FFDB catalogue with 174 source identities, 137 publisher map
  points, complete source-cell provenance and an offline producer. The default
  map build validates the capture and both cached products, records their
  hashes and keeps historical enrichment separate. Explicit historical
  selection remains available without automatic fallback. The integrated
  snapshot now contains 13,459 records, including 13,357 coordinate pairs.
  Source-specific permission, unspecified map precision and unresolved
  captured-container rights remain visible.

- Five hundred and ninety-nine source-inspected taxonomy statements across 135 entries, exact section
  and printed/PDF page locators, validated source metadata and offline detail
  display. Four hundred and eighty statements bind complete physical fields; integral PWR
  retains the source's most-or-all component qualification. HTGR and fast-reactor
  citations cover principles, design characteristics and technical challenges,
  with historical programme and fuel-development boundaries. Gas-cooled fast
  reactors retain the distinction between conventional start-up fuel and the
  refractory high-temperature target; fast-core classification does not imply
  absence of every moderating material. SCWR and VHTR statements preserve
  potential cycle/industrial-heat benefits and material-development boundaries.
  Salt entries distinguish dissolved fuel from solid-fuel fluoride cooling and
  retain design-specific circulation, fuel-treatment and decay-heat constraints. Heavy-water and graphite citations distinguish CANDU pressure boundaries,
  vessel-internal degradation, historical Magnox operation and RBMK accident
  analysis, and AGR material/inspection requirements. Research configurations
  retain geometric, dissolved-fuel, critical/subcritical and pulse-mode boundaries;
  EPFL and Mainz supply named operating examples without universal controls or
  licensing claims. Electrolyser and fuel-cell statements distinguish ion transport,
  thermal integration, fuel/catalyst constraints and stack durability; historical
  cost and lifetime targets remain separate from measured current outcomes.
  Chemical statements preserve ideal mixing and plug-flow assumptions, exothermic
  heat-release limits and process-specific cascade evidence. Stopping semi-batch
  feed is not treated as stopping the reaction; staged feeds and temperatures
  are options whose benefits depend on kinetics. Schema 1.3.0 audit exports
  distinguish known retrieval dates from retained-source inspection and retain
  every historical audit field and
  keep full entry review pending. Native metadata, exporter and serializer tests
  now run in the presentation validator at 100 per cent coverage.

- Complete seven-artifact industrial round-seven bundle, with 153 Swiss SFOE
  biogas plants and 268 Italian ARPAE biogas-classified bioenergy records,
  source-specific rights, native validation and offline map integration.
  Before the FFDB replacement, the map contained 13,438 records, including
  13,234 with coordinates.
  Original source cells and existing facility/company records are preserved.

- Ten company-depth profiles with 33 dated source citations, 60 field/source
  associations, source-specific rights notes and native build/validation CLIs.
  The gap review records metadata reviewed while preserving unknown prototype
  fuel, company-authored evidence limits and differing historical/current claims.

- Dated FusionBenchmark rights observation separating current copying
  restrictions from the unverified historical licence assertion; corrected
  source and consumer documentation without changing retained source cells.
- Coverage documentation reconciled against complete frozen inputs: 54 research
  overlays, 34 distinct fusion overlay targets (32 base and two additions),
  98 company records and explicit map-coordinate provenance boundaries.

- Isolated preflight rebuild of all 18 offline release products, with complete
  JSON/JavaScript and inventory comparisons, input preservation, bounded native
  processes, public Markdown checks and seven-line script header checks.
- `SOURCE_DATE_EPOCH` support for reproducing the shell inventory's UTC receipt.

- Complete Wikidata research-reactor source cache and isolated offline/live
  candidate builds, with explicit status labels and incomplete-source refusal.

- Source-pinned citations for 54 canonical Reactor project repositories, with
  explicit proposal, producer-maturity and dated public-link boundaries.

- Canvas map engine for the facility layer, in seven single-responsibility
  modules under `04_interactive_presentation/map/`: projections, coastline
  recovery, quadtree spatial index, density aggregation, viewport, canvas
  renderer and orchestration. No runtime dependencies; loads over `file://`.
- Equal Earth equal-area projection with forward and inverse transforms, and
  plate carrée retained as the basemap's own frame.
- Coastline recovery that inverts the bundled plate carrée basemap to
  geographic coordinates, allowing reprojection without additional geometry.
- Quadtree index supporting viewport culling and pointer hit testing across
  the full 12,813-record mapped dataset.
- Screen-space density aggregation with area-proportional glyphs, majority

- Keyboard map interaction: arrow-key panning, `+`/`-` zoom, `0` reset and
  `Enter` to open the focused record.
- Parallel visually hidden focusable record list and an `aria-live` region,
  so the canvas layer is reachable by assistive technology.
- 85 unit tests for the map engine, executed by `validate.sh`.
- `pyproject.toml` with strict `mypy`, NumPy-convention docstring rules and a
  100 per cent coverage floor, statement and branch.
- `LICENSE`, `COMMERCIAL-LICENCE.md`, `CHANGELOG.md` and `docs/internal/`.

### Changed

- Added a component-level rights map for the generated facility/company data,
  retaining each source's attribution, licence scope and exact input digest.
  Original editorial contributions and source data retain separate terms.
- Restricted the public historical FusionBenchmark base to its six compilation
  fields for all 146 identities. The excluded Wikidata values and coordinate
  notes remain in separate original custody. An explicit complete-bundle
  selection validates nine frozen inputs before offline historical reproduction.
- Reconciled public validation, coverage and threat-model documentation with
  the current source selection and bounded independent security disposition.


- Industrial facility builds require an isolated candidate destination and
  verify all six complete source counts, scalar observations and stable IDs.
  Offline snapshots reproduce the dated catalogue without network access.

- Public repository catalogue acquisition now validates the complete paginated
  source before preparing a separate dated snapshot and output bundle. Failed
  writes and buffered closes preserve the prior destination and remove the
  partial temporary file.

- Reconciled the Atlas portfolio and presentation licence/publication boundary.
- Classified a downloaded Recaptcha interstitial as catalogue-only rather than
  article full text. Downloaded third-party PDF/ZIP custody remains local and
  outside Git pending source-specific rights and hosting review.

- Taxonomy audit extended to every entry, and its findings acted on. The 11 entries added after the
  first pass now carry audit records, so none is marked `not-yet-audited`.
  Findings recorded: two entries carry cross-assigned sources, one merges two
  physically distinct classes, one states an evidence scope that reads as an
  established reactor architecture rather than an established neutron source,
  one understates historical operation, and one duplicates a combination of
  two parent geometries. All five findings were then applied: the merged entry
  was split, giving 135 entries; sources were reassigned per entry; and the
  beam-target generator's evidence scope now states explicitly that it is an
  established neutron source making no net-energy claim.
- `add()` in the taxonomy source accepts per-entry source and evidence-scope
  overrides. Sources were previously inherited family-wide, which is how two
  entries came to cite a reference documenting a different technology.
- Facility map renders to canvas instead of one SVG `<circle>` per record.
- Default map projection is Equal Earth rather than plate carrée.
- `validate.sh` verifies its required tools before running and executes the
  map engine test suite.
- `browser-check.py` asserts canvas engine state, projection equal-area
  property, keyboard reachability and cluster record conservation.
- SPDX headers applied to all Python, shell and JavaScript sources.

### Fixed

- `validate.sh` reported success when a checker was absent: the Slovak UI
  residue check depended on `ripgrep`, whose absence was read as "no matches"
  inside an `if`, so the check silently never ran.
- Facility points no longer carry a per-point drop shadow, which rendered
  dense regions as opaque mass.
- Keyboard access to mapped records no longer disappears above 500 rows.
- Cluster glyphs are capped below half the aggregation cell, so adjacent
  counts no longer overlap into an unreadable label.

### Security

- No credentials, tokens or keys are present in the repository.

- Retain 1,631 source-bound facility field assertions in schema 1.1.0, with
  per-field licences and capture dates. Distinguish published end use,
  feedstock and whole-plant fuel classification in search, details and exports.
  Frozen release validation does not depend on preparation fixtures.
